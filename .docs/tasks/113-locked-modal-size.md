## Problem

Author 在真机上打开 `配置 → yaml 编辑`，看到弹窗只占屏幕上半截，下方露出灰色背景与背后的主菜单；切回「可视化」tab 又变成满屏。桌面端同样：三个 tab 的内容长度不同，面板就跟着忽高忽矮，`取消/确认` 也悬在半空。

根因是**面板高度由内容决定**：`.modal__inner-2` 只有 `max-height`（桌面 `calc(100vh - 60px)`、≤600px `100vh`），没有固定高度；`.modal__button-bar` 靠 `position: sticky; bottom: -Npx` 吸底，内容比面板短时它不贴底，而是紧跟内容停下。

## Decisions

Author 逐轮确认（第 1 轮 Q1a/Q2a/Q3a，第 2 轮 Q4a/Q5b，第 3 轮全部按推荐）：

1. **面板高度恒等于上限**：移动端 = 可视视口高，桌面 = 可视视口高 − 60px。内容、tab、弹窗种类都不再影响面板大小。拒绝：只设最小高度（短弹窗不再半截，但切 tab 仍会跳）。
2. **全部弹窗参与**，含两行确认框与链接输入框。拒绝：只锁内容可变的少数弹窗（规则分叉、新增弹窗要再判断一次）。
3. **桌面同样锁死**，面板下方留白可接受。拒绝：桌面维持内容高度。
4. **内件一律不动**：yaml 编辑器（`min-height:160px`）、图片清理列表（`max-height:320px`）、ChatGPT 输出框（260/300px）保持自身尺寸，面板内留白是有意为之。拒绝：编辑器类撑满 / 全部撑满（一次改 5 类内件，失控）。
5. **矮窗口不做最小高度保底**：严格"视口高 − 60px"，内容区自己滚动。拒绝：低于某高度退回内容高度（同一语义在不同窗口下不一致，测试翻倍）。
6. **手机软键盘弹出时面板跟随可视视口收缩**，按钮栏始终可见；键盘收起自动恢复。
7. **不加高度过渡动画**（会与平台键盘动画打架，且波及切 tab/开弹窗）。

由锁高暴露出的必修项：**按钮栏必须真正钉在面板底部**，不能继续"内容短就悬在内容下方"。

契约已写入 `.docs/spec/frontend-conventions.md` 的 Modal Spacing and Sticky Bars（锁定尺寸 / 按钮栏贴底 / 软键盘跟随三条）。

## Out of scope

- 内件的固定高度（yaml 编辑器、图片清理列表、ChatGPT 输出框、模板编辑器）。
- 弹窗宽度上限（560 / 520 / 600 / 760px 等）与桌面居中宽度。
- 内容自身排版、字号阶梯（105 已定，不动）。
- 弹窗内的软键盘遮挡输入框问题（只保证按钮栏不被盖住）。

## Testing strategy

- `npm run build` 是唯一 CI 门槛（Jest 链已断，不要依赖）。
- 锁高是纯几何：真实 `dist/` 下用 `getBoundingClientRect()` 对 `innerHeight` / 可视视口比对，同一弹窗在三个 tab、长短两类弹窗、四个视口宽度下高度必须恒定；同时断言按钮栏 `rect.bottom` 贴面板底。
- 软键盘无法在无头环境真实触发：用 `Page.addScriptToEvaluateOnNewDocument` 桩一个 `visualViewport`（可变 height/top + resize 事件），断言面板收缩到该高度、按钮栏仍在面板内。这是能区分"真的跟随可视视口"与"只是 100vh"的唯一接缝——只缩小 `innerHeight` 的测法在纯 `vh` 实现下也会通过，不能作为证据。
- 105 已有的 `mobile-modal.mjs` 中两条断言会被本次决定反转（移动端 `max-height` → `height`；短弹窗"保持自然高度" → "同样满屏"），在同一批里就地更新，并在 105 卡片上标注被本批取代。
