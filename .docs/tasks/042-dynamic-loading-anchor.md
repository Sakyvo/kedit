# 042 动态加载批次锚卡(保页面不卡死)

## 目标重述

不再追求「打开 <1s」(ADR-0012 实测未达、且两条廉价路径被实验否决),改为
「**保页面不卡死**」:打开 80 万字文档时,主线程最长任务 ≤80ms,编辑器首帧
≤150ms,整个打开过程键入、左侧文件栏、上方工具条全部可交互。

真凶实测(真实样本 810,031 字符 / 10,802 段,桌面 dev):编辑器 cledit 一次同步
构建全部段落 DOM = 单个 3,256ms 长任务,预览侧合计仅 ≈163ms。所以本地冻结的
主项是**编辑器构建**,不是预览。

## 批次决策(grill 收敛,用户全数确认)

1. **机制保留**:批次 010 的文本模型/窗口 diff/分段器/TOC 行扫描/预览隐藏零渲染/
   窗口化挂载/渐进高亮全部保留 —— 它们正是本次手术的地基。
2. **新手术**:cledit 首次构建的建段循环拆成 rAF/idle 分片(每片 ~40ms 预算),
   首帧只挂载视区需要的段(≤300 段),其余分片补上。整个补齐期间一切交互可用。
3. **预览**:打开时预览面板显示「预览生成中…」占位;等编辑器首帧就绪后再开始
   依据可见性的转换 + 窗口挂载,绝不空白、也绝不抢主线程。
4. **开关更名+默认关**:`长文档分段加载(segmentedLoading,默认on)` →
   `动态加载(dynamicLoading,默认off)`。OFF = 完全现网行为,逃生通道不变。
5. **方向外**:编辑器窗口化(CodeMirror 6 级虚拟化)仍不做;遮罩加载不做。
